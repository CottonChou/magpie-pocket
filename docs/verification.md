# Magpie Pocket v1.0.2 验证记录

验证日期：2026-10-23。版本 `1.0.2` / code `3`，最低 Android 7.0 / API 24。

## 本轮完成

1. 真实连接默认启用可关闭的后台保活，采用低优先级前台通知、30 秒轻量心跳和最长单次 30 秒的退避重连。连接状态由应用持有；返回前台可恢复。偏好尚未加载时不按默认值抢先启动服务，快速切出时也不取消合法的待启动服务。
2. 路由自动跟随全局最新处理中请求，无处理中请求时展示最近已观察到的完成请求。组、供应商、账号、选路依据和上下文一起更新；历史固定与详情保持隔离，返回实时后恢复跟随。无数据、直接路由与缺失元数据各有明确状态。
3. 开关统一指定浅色 / 深色、开启 / 关闭、禁用各状态的圆点、轨道与边框；可读名称和状态分别提供，触控区域至少 48dp。
4. 设计 skill 包含参考图、完整规范、精确参数和交付检查；项目内置 `.agents/skills/magpie-pocket-design`，并提供可移植 ZIP。

## 原生运行验收

后台协议测试使用专用 Android 14 / API 34、Android 11 / API 30 模拟器和本地样例网关。Debug 只对环回测试地址放行 HTTP；Release 不包含该配置。未使用真实服务器地址、账号、CF Token 或 Web Key，不将本轮结果表述为生产服务器登录验收。

两个 Android 版本均已通过：

- 认证后自动渲染组 A，不出现手动选组控件。
- 按 Home 切到后台 34 秒，trace 与轻量心跳仍有新请求；返回后自动显示服务器已切换的组 B。
- 注入 5xx 后显示离线，恢复服务后自动连接，无需重新输入密钥。
- 关闭保活后，等待 5 秒清退，再持续观察 34 秒，没有新的后台请求；返回前台恢复。

Android 14 另外通过：拒绝通知权限仍可后台运行；保活开启 / 关闭分别冷启动并等待 12 秒，均无崩溃，服务状态符合偏好；首帧后立即按 Home，后台 trace 继续且服务存活。进程强制结束后重新打开，使用已保存连接恢复。

路由图同一区域比较：处理中两帧有 **449** 个变化像素；开启减少动态效果后为 **0**，数据和状态继续显示。浅 / 深色开关各开、关状态截图已检查，圆点清晰可见；主题颜色的圆点与轨道对比度均至少 3:1。

正式签名 APK 在 Android 11 验证 v1.0.1 → v1.0.2 直接覆盖安装，保留保存的显示偏好；概览、路由、用量、请求及明细均可使用。请求列表显示本地 `09:41:12`，明细显示 `UTC+08:00`。演示模式不启动前台服务。README 截图、动效与两种主题的偏好页来自该正式包的演示数据。

320dp 宽度、字体放大 1.3 / 1.5 的路由与偏好页已渲染检查；三个开关的可点区域均至少 48dp。该检查不等同于覆盖所有屏幕、厂商系统或无障碍组合。
