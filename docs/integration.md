# 接入说明

## 管理服务地址

客户端连接 Magpie 的 **Web 管理服务**，不是 `/v1` 模型推理网关。示例地址：

```text
https://your-magpie-admin.example
```

API 能力以运行时探测为准。协议参考 Magpie 提交 `ea6be1592706ea4a0dd6cd526acec0b5d1fb967e`，并兼容验证期间观察到的后续返回形态；不同部署可能缺少部分数据。

## 认证

### Magpie Web Key

应用使用 `POST /_magpie/sign-in` 提交 `key`，接受同源登录成功跳转与登录 Cookie，再访问受保护的管理 API。Cookie 留在当前连接的内存会话中；恢复连接时会重新登录。

Web Key 来自 Magpie 的启动链接 `/?k=...` 或部署环境的 `MAGPIE_WEB_KEY`。粘贴带 `?k=` 的完整地址时，应用提取密钥并规范化管理地址。

### Cloudflare Access

如果管理服务前面有 Cloudflare Access，在连接页展开对应设置，分别填写 Service Token 的：

- `CF-Access-Client-Id`
- `CF-Access-Client-Secret`

应用将其作为请求头发送到所配置的管理服务。CF 凭据用于通过前置 Access；如果 Magpie 仍要求登录，还需要自己的 Web Key。跨站登录跳转不会转发这些凭据。

连接测试完成受保护 API 探测后才保存。401、403、登录 HTML、网络不可达和非预期 JSON 会显示不同提示；不会把失败连接保存为成功。

### 本地存储

连接凭据由 Android Keystore 支持的 EncryptedSharedPreferences 保存，显示偏好使用 DataStore。应用不允许系统备份；账号默认打码，Cookie 不持久化。

加密存储不可用时不保存连接，也不退回明文存储；仍可使用演示模式。旧版遗留的明文偏好会在启动时清除，不迁移其中的凭据。保存失败不会切换当前连接。

## v1.0.1 安装与签名变更

v1.0.1 更换了发布签名，旧签名已停止使用。已经安装 v1.0.0 或此前本地交付版本的用户，需要卸载旧版后安装 v1.0.1；卸载会清除原有连接和偏好，请提前保留自己的服务地址及登录凭据，并在新版重新输入。新安装用户可直接安装。请从本项目的 [Releases](https://github.com/CottonChou/magpie-pocket/releases/latest) 下载。

## 查询接口

| 能力 | 接口 | 当前映射与行为 |
|---|---|---|
| 必需的管理能力探测 | `GET /api/state` | 版本、时区；失败时不建立连接 |
| 路由组 | `GET /api/groups` | 支持字符串成员及 `memberInfo` 元数据、策略和亲和性 |
| 实时路由 | `GET /api/gateway/trace?after=seq&wait=1` | 增量合并路由；兼容无 `epoch` / `ids` 的部署；序号回退清理缓存；无显式保留列表时保留最近 60 条 |
| 历史路由 | `GET /api/gateway/history` | 数据范围由上游决定，不把接口缺失视为完整历史 |
| 路由详情 | `GET /api/gateway/route?id=...&day=...` | 优先使用实时缓存；历史查询按可用参数读取；过期详情显示不可用 |
| 用量 | `GET /api/usage` | 请求、错误、首响累计/样本、Token 和趋势；支持 `series` / `hourly` 等返回别名 |
| 请求账本 | `GET /api/usage/requests` | 支持 `rows` / `records`、分页、搜索及状态信息 |
| 额度 | `GET /api/usage/quotas` | 支持根数组或包装对象，区分百分比、小数额度、无限制及未知值 |

可选能力只在真正的 404 时降级，认证、传输和解析错误继续向上报告。长轮询使用独立的较长读取超时；上游序号不变时增加暂停，避免忙轮询。

## 时间与实时界面

RFC3339 时间按实际时间点解析，然后转换为手机本地时区。`Z` 不代表“已经是本地时间”；已带 `+08:00` 的输入也不会被重复偏移。日期选择器保留 Android 要求的 UTC 日期编码。

路由图从同一个 trace 缓存获得摘要与完整详情，优先跟随当前组最新处理中请求。改道后的实际账号、供应商、状态、选路依据和上下文同步更新。历史请求保持固定，点击返回实时后恢复跟随。减少动态效果、系统动画关闭、后台或离线时停止动画。

## 只读范围

路由组切换、日期、筛选和主题都是本地查看操作。客户端不提供服务端路由策略、账号和模型配置的写入、请求重放或解除冷却等操作。登录交换属于建立现有管理会话。


## 后台保持连接与恢复

真实连接默认启用“后台保持连接”，可在显示偏好中关闭。前台服务使用低优先级常驻通知，Activity 与服务共享同一份应用级连接状态，不因普通切出或 Activity 重建重新创建登录会话。通知不展示服务器地址、账号或凭据。

服务启动在用户可见的前台完成；Android 14 声明 `dataSync` 类型及相应权限。每 30 秒通过受保护的 `/api/state` 做轻量校验，临时网络/5xx 故障退避重试，最长单次等待 30 秒。401/403、Cloudflare 拒绝及不兼容响应保持明确错误，不无限重复错误凭据。关闭保活后，应用切到后台会停止网络任务；返回前台自动恢复。

服务与通知权限提示均等待已保存的偏好加载完成，避免把默认开启误当成用户的实际选择。服务接到启动请求后立即提升前台，再判断继续或停止，以满足 Android 的启动时限。

Android 13+ 仅在真实连接需要后台保活时请求通知权限。拒绝通知权限不阻止前台服务启动，系统仍有运行中应用入口；这与普通通知是否可见是两个权限行为。参见 [Android 通知权限说明](https://developer.android.com/develop/ui/views/notifications/notification-permission)。

当前配置下，从最近任务移除应用也会停止保活服务。系统强制停止会结束进程；深度休眠、厂商省电策略可能延后网络，因此不承诺永不断线。应用重新打开时使用已加密保存的连接恢复；没有使用永久唤醒锁或强制要求关闭省电设置。参见 [Doze 与 App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby)。

v1.0.2 延续 v1.0.1 的新签名，可直接覆盖安装；只有 v1.0.0 及更早的旧签名版本需要卸载重装。

## 自动路由

路由页不再显示手动分组选择。正在处理的真实请求优先，并按真实开始时间自动选择最新请求，同时更新组、供应商、账号、尝试和上下文；没有处理中请求时展示最近已观察到的已完成请求。缺少组元数据时显示真实组标识，无组请求显示“直接路由”，无请求显示等待状态。

历史固定和请求详情保持原请求，不被新的其他组抢走；“返回实时”恢复全局自动跟随。网关 epoch 与连接身份用于隔离详情，不能在重启后复用同 ID 的旧请求。
